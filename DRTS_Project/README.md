# Hierarchical Real-Time Scheduling Analysis Tool

This archive contains a set of tools for simulating, analyzing, and evaluating hierarchical real-time scheduling systems. The tools allow you to test and validate task scheduling algorithms across different processor architectures.

## Contents

* **Simulator**: A discrete-event simulator for hierarchical scheduling systems
* **Analyzer**: A schedulability analysis tool using formal methods
* **Analysis Scripts**: Tools for analyzing simulation results and generating reports
* **Data**: Test cases 1-10 with various configurations
* **Results**: Output generated by test cases 1-10 from simulation and analyzer runs
* **Visualizations**: Graphical representations of performance metrics

## Key Files

* `simulator.py` - Event-driven simulator for hierarchical scheduling systems
* `analyzer.py` - Formal schedulability analysis using demand-bound functions
* `analyze_results.py` - Statistical analysis and visualization of results
* `scheduling_formulas.py` - Mathematical formulas for schedulability analysis
* `component_analysis.csv` - Statistical summary of component performance metrics
* `avg_response_time_boxplot.png` - Visualization of average response times by component
* `max_response_time_boxplot.png` - Visualization of maximum response times by component
* `max_jitter_comparison.png` - Comparison of maximum jitter across components

## Running the Tools

### Running the Simulator

The simulator can be run against test cases to verify schedulability empirically:

```bash
python simulator.py --input_dir data --output_dir results
```

This will process all test cases in the `data/` directory and output results to the `results/` directory.

### Running the Analyzer

The analyzer performs theoretical schedulability analysis:

```bash
python analyzer.py --input_dir data/3 --output_dir results/3
```

You can specify a particular test case to analyze. The epsilon value can be adjusted to control numerical precision:

```bash
python analyzer.py --input_dir data/3 --output_dir results/3 --epsilon 1e-9
```

### Analyzing Results

After running simulations, you can analyze the collected results:

```bash
python analyze_results.py
```

This generates the `component_analysis.csv` file and several visualization plots in the root directory.

## Understanding the Results

* `component_analysis.csv` contains detailed statistics for each component type including:
  * Average and maximum response times
  * Jitter measurements
  * Schedulability ratios
* The visualization files provide graphical representation of:
  * Response time distributions
  * Jitter characteristics
  * Component performance comparisons

## Input Format

The system uses three main input files for each test case:

1. `architecture.csv` - Defines processor cores and their scheduling policies
2. `budgets.csv` - Specifies components and their resource allocations
3. `tasks.csv` - Describes individual tasks with timing parameters

## Output Format

The main output is `solution.csv` which contains:

* Task-level schedulability results
* Response time measurements
* Component-level schedulability

## Performance Classification

Components are classified into three categories based on their average response time:

* Low Latency: < 10ms
* Medium Latency: 10-50ms
* High Latency: > 50ms

The analysis also identifies components with performance issues such as high jitter, missed deadlines, or excessive response times.
